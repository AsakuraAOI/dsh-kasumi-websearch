# Kasumi Web Search

给 DSH 原有的 `web_search` 和 `web_fetch` 接入搜索中转服务。搜索返回候选来源，Agent 自己决定哪些页面值得继续阅读。

## 搜索与读取分开做

一次搜索返回网页标题、链接、摘要与来源标记。需要原文时，再对选中的 URL 调用 `web_fetch`；搜索阶段不会自动规划研究、遍历链接或替 Agent 抓取页面。

```text
web_search → 选择来源 → web_fetch → 根据实际读到的内容回答
```

搜索保留后端来源顺序，普通请求最多两个并发。日期、版本或比较类问题也遵循同一流程，没有隐藏的研究模式。

## 接入 DSH

支持 **DSH 0.2.1-rc.1 / rc.2**，当前版本 **0.3.14**。

```sh
dsh plugin --profile desktop add 'github:AsakuraAOI/dsh-kasumi-websearch'
```

按管理器提示重启，在插件配置中填写可用的中转地址和 DSH 模型凭据引用。凭据引用的默认值见 [组合配置](cordis.patch.yml)；仓库不包含密钥。

| 配置 | 默认值 | 说明 |
|---|---|---|
| `baseURL` | 代码中提供的中转地址 | 提供搜索与网页读取接口的 HTTPS 服务 |
| `apiKeyRef` | 复用模型通道的凭据引用 | 在 DSH 凭据服务中配置 |
| `timeoutMs` | `20000` | 搜索超时，毫秒 |
| `maxResults` | `10` | 单次请求最多返回的标准来源数 |

已有模式包含网页工具时即可使用，无需切换聊天模型或新增研究预设。

## B 站内容怎么处理

相关查询可以额外返回最多 3 条 B 站搜索结果，和普通网页使用独立配额。对规范视频链接，网页读取优先取得公开视频信息和少量相关推荐。

这里读到的是**标题、作者简介和页面信息**。结果会标记实际读取范围，不下载视频、音频或字幕。问题涉及具体演示、画面或完整内容时，需要另外使用视频阅读工具。

## 结果里的边界

- 搜索摘要与网页正文分开标记，抓取失败不会用摘要冒充原文。
- 页面日期保留来源语义，不自动解释成事件发生日期。
- 部分搜索源失败会保留状态；空查询由 DSH 汇总提示。
- 标题、简介和正文都是外部数据，不能作为执行指令。

禁用或卸载时，请同时恢复 DSH 的搜索/读取提供方选择，避免网页工具继续引用已经移除的服务。

开发验证使用伪造响应，不会发起真实搜索：

```sh
npm test
```
